How to read the bars

Every bar answers one question: how close is this object to the finish line its own repository declares? The finish line depends on the kind of work, so every card says what 100 % means. Open any card to see the evidence the number rests on, taken from the repository itself; where two notes disagree, the most recent one counts.

Reading the repository names

<platform>-<subject>, where the platform is the target: psx-lba is Little Big Adventure running on the PlayStation, pc-victorious a Wii game brought to PC. -doc is documentation only, -re a reverse-engineering devlog, and a -kit a game-agnostic toolkit named after the console it stands in for. In this catalogue a ported game sits in the room of the machine it comes from.

No repository contains game assets, ROM data or copyrighted content. Every port is BYOA, bring your own assets: it needs a copy of the game you already own.

Method and attribution

This is a human + LLM collaboration, stated openly because the honesty is the point. I bring the domain knowledge and the direction: knowing these machines, recognising a genuine first, deciding where to dig. Claude brings the implementation across architectures I could not otherwise approach. Neither side reaches these results alone.
